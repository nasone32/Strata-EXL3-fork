# Short Qwen EXL3 release benchmark

Hardware: Ryzen 9 7950X, 96 GB installed RAM (93 GiB reported by Linux),
RX 7900 XTX on the main x16 slot and a second RX 7900 XTX on a chipset x4 link.
Linux, HIP gfx1100, ROCm core-7.14. Models are on local SSDs.

This is one short batch, not a repeated statistical study. Every prompt has two
runs in the same engine process. Both runs are retained. The second follows the
first so the expert cache can warm up; the OS file cache is not flushed. The
published build ran first. No other GPU inference or compilation ran alongside the
measured requests. Startup is excluded from throughput.

## Two GPUs

- Baseline: the published `amd-exl3-community` commit `3be4442681404ce7a345d6e74f0e4abe62ba19ed`.
- Candidate: this release's engine, with automatic gfx1100 fast defaults and full
  registered RAM residency (`STRATA_EXL3_RESIDENT=all`).
- Native experts in both arms; CPU assistance and peer adaptation off.
- Same primary/peer cache sizes: 165/10200 (3.05 bpw), 104/7200 (4.05 bpw).
- Same 65536-token context capacity, int8 KV, prefill chunks 8192, primary/peer
  reserves 2048/4096 MiB, initial expert profile and matching n-gram table.
- MTP runtime shared across arms, window 4, probability floor 0.5.
- This is a comparison of release profiles, including residency, not an isolated
  claim about any one optimization. Full residency moves expert reads to startup.

## One GPU

The same candidate binary and 4.05 bpw quant, GPU 0 only, primary cache 104 slots,
same context/MTP/prompt settings. Native experts with CPU assistance off versus
runtime RAM-repacked experts with CPU assistance on: 8 workers, hybrid quota 2,
minimum misses 1, CPU cache 0, swizzle off. Both use full RAM residency.

The CPU-assisted run uses `STRATA_QWEN_BAND8=memory`: the source model is read and
repacked into RAM at startup, with no packed disk files. This compares **CPU help
and repacking together**. It does not isolate a storage-layout gain, and startup
conversion time is not included in tokens/s.

## Requests and accounting

- CODE: `write a bubblesort algorithm in C code`
- PROSE: `explain a PID controller ELI5`
- CODE and PROSE: greedy, seed 1234, maximum 512 generated tokens. The limit is
  intentional; this is not a full-answer correctness evaluation.
- PREFILL32K: the deterministic synthetic document generated by
  `tools/exl3/bench.py`, exactly **32768 input tokens**, followed by up to 16 tokens
  of generation. Only prefill throughput belongs in the prefill table.
- Conversation/checkpoint caches are disabled. Every recorded request must have
  `reused_tokens=0`, `read_tokens=input length`, and a positive output count equal
  to the recorded output-ID count. Prompt-cache reuse is not fresh prefill.
- Throughput comes from the engine's DONE fields, not total process wall time.
  The JSON records preserve counts, times, draft acceptance, output IDs and text.
- Outputs are not assumed identical between builds or CPU policies. The main
  README discloses differing continuations. These are observed throughputs, not
  byte-identical causal speedup or model-quality claims.

## Reproduce

Build the old commit and this release with the same compiler, gfx1100 target and
pinned llama.cpp checkout. Activate the Python environment with this repository's
requirements installed. Free the GPUs, then run:

```sh
python tools/bench_exl3_release.py \
  --baseline /path/to/old-build/strata --candidate /path/to/new-build/strata \
  --model-3 /path/to/qwen-3.05bpw --model-4 /path/to/qwen-4.05bpw \
  --tokenizer /path/to/converted-tokenizer --mtp /path/to/mtp-runtime \
  --output /path/to/new-results --max-new 512
```

Repeat with `--single-gpu-only` and a different output directory for the one-GPU
comparison. The runner refuses to overwrite an existing results directory and
stops on engine errors or inconsistent counts. No model download or disk repack
is performed. The raw local engine logs remain available separately; published
configs use path placeholders rather than the developer's home directories.
